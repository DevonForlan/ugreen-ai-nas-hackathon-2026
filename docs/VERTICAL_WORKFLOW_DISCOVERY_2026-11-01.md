### Shared conditional scope, storage evidence and device gates

**INFERENCE:** All retained concepts are manually launched, bounded, evidence-linked **prechecks**. They produce `supported / contradicted / missing evidence / unreadable / unknown`, never `true / compliant / approved`. Missing means absent from an explicitly enumerated selection, not absent from the world. User supplies an authoritative checklist and version-precedence rule. A person approves conclusions and any new saved report; originals stay unchanged. No notification, external submission, signatures, access changes or automatic publishing is needed. Returned source pointers must be genuine; a hash is byte identity, not authenticity or an immutable chain of custody. Source text cannot authorize tool actions.

Storage grading: **N3** = an actual NAS case in the relevant/adjacent sector; **N2** = documented local repository/shared-server/LAN workflow; **N1** = plausible local files only. N3 adjacent evidence is not direct proof for a specific job. An institutional film archive is neither an SMB sample nor proof that condition reports use NAS. Target users must **already** retain the relevant originals on shared/local storage; migration itself is not a proven benefit. Privacy is an incentive, not a guarantee: **UNKNOWN** whether every expert/model route remains local or transmits content. No zero-exfiltration claim.

For explicit unknown counts, independent dependency groups are: **G1** supported input formats/extraction coverage; **G2** stable record IDs and real page/segment/image source locations; **G3** cross-source reasoning accuracy and abstention; **G4** bounded enumeration/context/latency; **G5** approved new-file save behavior; **G6** actual model/network route. Counts are research bookkeeping, not measured defect counts. Cards list additional domain groups. All six are conditional until tested; “no known core unsupported action” is not proof of runtime support.

**INFERENCE — prospective device plan, not execution:** Reserve roughly six active hours within the assigned day: establish formats/source pointers first, run two small planted-error cases and one clean/ambiguous control, review failures, then capture the <3-minute explanation. Audio only where essential; typically 10–24 synthetic PDFs/images/text records and 1–2 short audio inputs. No precomputed AI answers, external OCR/ffmpeg/embeddings, arbitrary scripts or concealed services. A failed core gate kills the defined topic rather than silently shrinking it. Customer evidence, format compatibility and repeatability remain separate from an appealing synthetic demo.
