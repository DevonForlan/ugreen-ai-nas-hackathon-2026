## 3. Core research question

Research the following question directly:

> Which professional workflows naturally keep authoritative, long-lived, multimodal source material on NAS/shared local storage, and repeatedly need cross-file evidence reconciliation before a human can complete a real task?

A valid target should ideally satisfy most of these:

- NAS or shared local storage is already part of normal practice.
- The stored originals are long-lived and reused across time.
- Data is multimodal or cross-format.
- The task requires more than search/summarization.
- A wrong file, wrong version, conflicting source, unread record or missing support causes real rework or risk.
- Existing vertical software does not eliminate all local-file review.
- Users repeatedly review the same authoritative corpus or project packet.
- General AI can help, but repeatedly preparing/uploading/reattaching the correct files creates workflow friction.
- Human review is still necessary.
- A small bounded dataset can demonstrate the problem in under three minutes.
- The UGREEN public Skill capabilities can plausibly operate on the required file types without hidden custom code.

Do not force a fit.

## 5. Eight required questions per vertical

Answer all eight for every vertical.

### Q1 — Do these users really use NAS / shared local storage?

Find direct evidence where possible:
- NAS vendor case study
- professional workflow documentation
- storage architecture documentation
- practitioner discussion
- institutional technical documentation

Classify storage evidence:

- **N3 — Direct NAS evidence**
- **N2 — Shared local/server/file-storage evidence**
- **N1 — Plausible only**
- **N0 — Not established**

Do not promote N1 to fact.

### Q2 — What authoritative data actually lives there?

Identify concrete file/data types, for example:
- RAW / video / audio
- PDFs
- project records
- drawings
- supplier documents
- photos
- transcripts
- instrument exports
- collection records
- evidence media

Distinguish:
- authoritative original
- export/copy
- working derivative
- cloud-system mirror

If unclear, mark UNKNOWN.

### Q3 — Is there a real cross-file evidence-review job?

Look for real tasks such as:
- source checking
- version reconciliation
- record completeness
- identity matching
- handoff review
- contradiction checking
- condition comparison
- sample/source mapping

Reject a vertical if the only strong problem is:
- search
- storage
- backup
- basic tagging
- generic summarization

### Q4 — How is the job done today?

Identify current workflow and tools:
- spreadsheets
- shared folders
- DAM/MAM
- Procore / Autodesk
- ELN/LIMS
- case systems
- collection systems
- manual checklists
- email exports
- cloud project tools

Do not assume manual work if evidence is absent.

### Q5 — What remains awkward or incomplete?

This is the key gap question.

Find whether users still need to:
- export records
- reconcile files across systems
- inspect unmanaged shared folders
- verify local originals
- compare current versus stale versions
- map physical/photo/document identity
- track unread or missing evidence
- reassemble evidence packets repeatedly

The gap must be supported by evidence or clearly labeled ASSUMPTION.

### Q6 — Why is general AI not enough operationally?

Do not argue that general AI cannot reason over files.

Instead test possible workflow friction:
- repeated file selection/upload
- stale versions
- source identity instability
- large corpus / data gravity
- repeated review over persistent originals
- multiple team members
- local authoritative copies
- failed-read visibility
- version continuity
- saved review artifact beside source data

If these are not material, say so.

### Q7 — Can this be shown in a <3-minute Round 2 demo?

Define a minimal demo with:
- 5–10 files
- 1 planted contradiction
- 1 clean control
- 1 missing/unread/uncertain case
- 1 human review moment

Reject scenarios requiring lengthy domain education or unsupported specialized parsing.

### Q8 — Can the value be explained in one sentence?

Write one sentence in this form:

> Before [real task], verify that [authoritative NAS data] actually supports [specific claim/handoff/decision], and show conflicts, unread evidence and uncertainty before a human decides.

If the sentence is vague, downgrade the vertical.

## 6. Mandatory tests

### Test A — NAS Removal Test

For every vertical ask:

> If the exact same workflow used Google Drive, Dropbox, SharePoint, a mounted local folder, or a general file-aware AI workspace instead of NAS, what meaningful value is lost?

Possible valid answers:
- very large media already resides on NAS
- repeated use of the same long-lived local authoritative corpus
- local network collaboration over original assets
- costly repeated data movement
- project history/version continuity tied to local source
- existing operational storage architecture

Invalid answer:
- "the files are on NAS"

Classify:
- **PASS**
- **WEAK PASS**
- **FAIL**

### Test B — SaaS Dominance Test

For every vertical identify the strongest vertical incumbent.

Ask:

> If a user already operates the dominant vertical system correctly, why would this NAS Skill still be useful?

Examples:
- Procore / Autodesk
- DAM / MAM
- ELN / LIMS
- collection-management systems
- e-discovery / investigation systems

Classify:
- **PASS** — a credible residual workflow remains
- **WEAK PASS** — residual gap is plausible but unproven
- **FAIL** — incumbent already owns the workflow and NAS adds little

### Test C — General-AI Substitution Test

Assume ChatGPT / Claude / Gemini receives the same bounded files and strong instructions.

Ask:
- Can it produce the same evidence table?
- Can it identify contradictions?
- Can it mark uncertainty?
- Can it preserve citations/source references?

Then identify only the **operational** NAS advantage that remains.

Classify:
- **PASS**
- **WEAK PASS**
- **FAIL**

### Test D — Generic Hackathon Collision Test

Estimate whether a generic prompt like:

> "Give me innovative AI NAS ideas for this profession"

would readily produce the same underlying workflow.

Classify:
- LOW
- MEDIUM
- HIGH

Do not award LOW simply because the sector is obscure.
