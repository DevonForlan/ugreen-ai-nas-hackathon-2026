## 3. Validation target

Validate this exact workflow:

### Trigger
A documentary script has changed shortly before picture lock / final editorial approval.

### Reviewer needs to re-check
- whether revised factual claims still match the exact interview/source wording,
- whether the cited source is still the current/approved version,
- whether an archival asset ID still corresponds to the intended source,
- whether different sources now conflict,
- whether a source is unreadable or unavailable,
- whether a claim became broader than the evidence actually supports.

### Proposed SourceWeave 2.0 output
For each revised claim:
- CLAIM
- SUPPORTING
- CONTRADICTING
- SOURCE LIMITATION
- UNREAD / FAILED SOURCE
- VERSION / ASSET ID ISSUE
- UNCERTAIN
- HUMAN DISPOSITION
- exact source pointer where genuinely available

Do not claim truth, legal clearance, rights clearance, journalistic approval, or automatic publication authority.

## 6. Fair baseline tests

### A. Same-folder General-AI Test
Assume a capable file-aware ChatGPT / Claude can access the same authorized project folder.

Give it the same:
- latest script,
- prior checked script,
- interview transcript,
- source PDF,
- archive metadata sheet,
- asset index,
- source checklist,
- output instructions.

Ask whether it can:
- identify changed claims,
- compare them to sources,
- surface contradictions,
- mark uncertainty,
- produce a source-linked review table.

Do not handicap the baseline.

Then identify what SourceWeave retains that is operationally meaningful.

If the answer is only:
- prewritten prompt,
- prettier table,
- four status labels,
- saved Markdown,

the differentiation fails.

### B. Trint + MAM Test
Assume the team correctly uses Trint plus Axle/another MAM and a normal review tool.

Ask:
- what exact step still requires repeated manual cross-source reconciliation?
- is that step recurrent?
- does NAS access reduce real preparation work?

If no material residual remains, downgrade or DROP.

### C. NAS Removal Test
Replace NAS with:
- Dropbox / Drive,
- SharePoint,
- mounted local/shared folder,
- MAM-managed storage.

What meaningful advantage disappears?

Valid answers must be operational, e.g.:
- large originals already live on NAS,
- repeated re-check over long-lived source corpus,
- no duplicate export/copy step,
- stable team source location,
- cross-project historical archive.

Invalid answer:
- "because the files are on NAS."
